# cutqc · 成片质检

剪完的片子丢进来，自动查三类最常见的剪辑事故，出一份能点时间码跳转的网页报告：

1. **闪帧**：孤立闪帧（1–2 帧）、剪辑点附近的碎镜头、单独的黑帧 / 白帧
2. **声音切点**：爆音 / 咔哒、切在字中间（吞字）、尾音被硬截断、切点两侧音量跳变、空白过长
3. **字幕对齐**：字幕早出 / 晚出、提前消失 / 拖太久、字幕文字和读音不一致、字幕处没人声、有人声没字幕、字幕跨剪辑点；并输出一份**按声音重新卡时间的字幕**

不绑定任何剪辑软件和剪辑稿格式：只要成片就能跑。另外给剪辑点列表，或字幕文件，结果会更准。

## 安装

需要先装 [uv](https://docs.astral.sh/uv/)（Python 工具管理器，Mac / Windows / Linux 都有）。然后一条命令装好，之后在任何文件夹都能直接用 `cutqc`：

```bash
uv tool install git+https://github.com/<你的用户名>/cutqc
```

- 更新到最新版：`uv tool upgrade cutqc`
- 卸载：`uv tool uninstall cutqc`
- 私有仓库：先在这台电脑上登录过 GitHub（`gh auth login`），uv 会用同一套凭据拉代码
- ffmpeg：系统里有就用系统的，没有会自动用安装包自带的
- 第一次做语音识别时会自动下载识别模型（small 约 500MB），之后不用再下

开发 / 跑压力测试时，在仓库目录里用本地环境：

```bash
git clone https://github.com/<你的用户名>/cutqc && cd cutqc
uv venv && uv pip install -e .
.venv/bin/cutqc --help
```

## 用法

```bash
cutqc 成片.mp4                                   # 只查闪帧 + 声音（按镜头切换推测切点）
cutqc 成片.mp4 --cuts 剪辑点.txt                 # 给剪辑点：只盯剪辑点，误报少很多
cutqc 成片.mp4 --cuts 剪辑点.txt --subs 字幕.srt # 三项全查
cutqc 成片.mp4 --start 600 --dur 120             # 只查 10:00 起的 2 分钟
```

报告默认在视频旁边的 `<文件名>_质检/` 里：

| 文件 | 内容 |
|---|---|
| `质检报告.html` | 按严重程度排序；点时间码跳到视频那一刻；闪帧附帧条、声音附波形 |
| `修正清单.csv` | 同样的问题列表，方便在剪辑软件里逐条改 |
| `issues.json` | 机器可读，给自动修复脚本用 |
| `<字幕名>.按声音修正.srt` | 匹配可靠的句子按声音重新卡了时间 |

有“高”级问题时退出码为 1，可以接进批处理。

## 剪辑点列表格式（`--cuts`）

成片时间轴上的切点（秒）。支持：

- `.txt`：每行一个时间，`12.5` / `0:01:02.300` / `0:01:02:15`（时:分:秒:帧）
- `.csv`：列名含“切点 / cut / 时间 / time / 出点”的列，或第一列能读成时间的
- `.json`：短剧工具包的剪辑稿（`clips` 里的 `vin/vout/speed`），或 `{"cuts": [...]}`
- `.edl`：CMX3600（取 REC IN）

## 选项

| 选项 | 说明 |
|---|---|
| `--only flash,audio,subs` | 只跑某几项 |
| `--audio-cuts 文件` | 声音剪辑点和画面不一样时单独给（J/L 剪）。用短剧工具包剪辑稿时会自动算，不用给 |
| `--asr small\|medium\|none` | 识别模型。`none` 不识别：声音项只做波形检查，字幕项跳过 |
| `--near 0.5` | 剪辑点前后多少秒内的碎镜头算“剪辑造成” |
| `--lang auto` | 识别语言，默认自动判断（中文 / 英文短剧都行）；可指定 `zh`、`en` |
| `--out 目录` | 报告目录 |

识别结果缓存在 `~/.cache/cutqc/`，同一个视频重跑不用再识别。

## 压力测试

改了判定逻辑或阈值之后，跑一遍压力测试，确认没有“修好一处、弄坏另一处”：

```bash
.venv/bin/python tests/bench.py          # 快速版：闪帧 + 声音 + 格式 + 真实片（不做语音识别）
.venv/bin/python tests/bench.py --full   # 完整版：再加字幕用例、长片漂移，每类故障多重复几次
.venv/bin/python tests/bench.py --only 陷阱   # 只跑某一组 / 某些用例
```

| 组 | 内容 | 合格标准 |
|---|---|---|
| 故障-闪帧 | 从真实素材截片段埋问题：插 1–2 帧别的镜头、剪辑点 1–5 帧碎镜头、黑帧 / 白帧、只闪画面一角 | 全部检出，时间码误差 ≤1 帧 |
| 故障-声音 | 咔哒声、尾音硬截断、音量突然差 20dB | 检出 |
| 陷阱 | 正常剪辑：快切蒙太奇、闪光灯、闪白转场、黑场过渡、快速摇镜头、J/L 剪、加了淡入淡出的硬切 | 不许报“高” |
| 格式 | 23.976–60 帧、变帧率、竖屏、4K、HEVC、ProRes、MKV、无音轨、单声道、5.1、1.6 秒极短片、中文空格路径、只查一段、剪辑点超出时长、剪辑点文件各种写法、40 段拼接长片 | 不崩溃、照样检出、时间码误差 ≤1 帧 |
| 字幕 | 中文解说原片 + 原字幕截 40 秒窗口，故意改坏：晚 0.9 秒、早 1 秒、文字全错、漏一句、提前消失；GBK / BOM / ASS / 空文件 | 全部检出；干净窗口不报“高” |
| 真实片 | `tests/labels.json` 里人工确认过的位置 | 按标注 |

- 素材在 `tests/bench_sources.local.json` 配置（复制 `tests/bench_sources.json` 示例改路径；`.local.json` 不会上传），越多样越好（横竖屏、不同帧率、对白 / 解说 / 音乐）。镜头普遍很短的素材（例如 5 秒一段的 AI 生成片段），测试片会自动缩短。
- 测试片生成后缓存在 `~/.cache/cutqc/bench/`，第一次很慢（要在素材里找合适的镜头），之后只跑用例。
- 每次结果在 `tests/results/<时间>/成绩单.md`，并和上一次同类运行比较“变差 / 变好”的用例。
- 以后剪片时人工确认过的误报 / 漏报，补进 `tests/labels.local.json`（格式见示例 `tests/labels.json`）（写视频、时间窗口、哪类不许报“高”或必须报出），回归测试就会一直盯着它。

另有一个最小自检：`.venv/bin/python tests/make_synth.py 任意素材.mp4 /tmp/synth` 造一段埋了问题的测试片。

## 判定说明

- **闪帧**：镜头切换要同时满足三条：画面差异大、比附近帧变化大很多、颜色分布明显变了。附近的重复帧不参与比较，所以转过帧率的素材（有 1-2-3 帧重复节奏）在快速摇镜头时不会误判成碎镜头。按视频真实帧率逐帧比较缩小画面，分 4×4 块取最大差值，避免小面积闪烁被整帧平均掉。连续一串短镜头会被当作原片快切，降为“低”。给了剪辑点时，离剪辑点远的碎镜头会降级，因为多半是原片自带的。画面突然变亮的，会标注“可能是原片闪光特效”。
- **声音**：需要逐字识别才能判断“切在字中间”，而且识别时间不可靠的词不参与判断（一个词超过 0.8 秒，或置信度低）。切点处声音频谱如果是连续的（J/L 剪、或做了淡入淡出），只报“中”并提示人工听一下。“音量跳变”只在切点两边都有人说话时才报“中”，否则多半是正常的场景声音变化，报“低”。
- **字幕**：逐字识别结果和字幕逐句模糊匹配，按拼音比对（同音错字也能对上），会统一繁简，并把数字统一成中文读法（1,000 → 一千）。先用匹配好的长句估一个识别时间的整体偏差（faster-whisper 一般晚 0.1–0.2 秒）再判断早出晚出。纯语气词（啊、哎……）不判。只有匹配率 ≥60% 的句子才会在修正版里改时间。

## 限制

- **硬字幕**（烧在画面里的）目前不查。要先识别画面上的文字，这个功能计划第二期做。
- 目前只在 macOS（Intel）上完整测过。Windows / Linux 上代码路径相同（Mac 才会用硬件解码），但还没实测。
- Intel Mac 没有独显，语音识别是最慢的一步：`small` 模型处理 10 分钟视频大约要几分钟到十几分钟。有 NVIDIA 显卡时会自动用 GPU。
- 背景音乐很响、或者多人同时说话时，识别不准，字幕项可能误报“对不上”。干净字幕窗口里，平均每个 40 秒窗口还会有约 3 条“中”级提示，需要人工过一眼。
- 埋在很响的音乐里的轻微咔哒声可能漏报（尖锐度和正常声音分不开，人耳也不太容易听出来）。压力测试里每个素材各有 1 例属于这种情况。
